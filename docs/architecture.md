# 燕中生态架构

本文定义生态长期稳定的系统边界、模块模型和依赖方向。当前完成度见 `燕中生态项目关系.txt`，实现缺口见 `architecture-review.md`，接口细节见 `contracts.md`。

## 架构原则

1. **领域归属优先**：先确定数据与规则属于谁，再选择框架和部署方式。
2. **稳定核心、可替换边缘**：身份、账本和燕中协议保持稳定；供应商、传输、存储和界面通过适配器替换。
3. **统一入口、分层执行**：所有生态承担责任的 AI 调用进入统一 API 网关；使用层负责语义编排，设施层负责协议与路由。
4. **显式契约**：跨仓库只通过版本化 API、事件和公共 schema 协作，不读写彼此数据库。
5. **渐进模块化**：新功能沿既定模块边界落地，并持续迁出已登记的集中式实现。
6. **默认最小权限**：能力、插件、工作流和凭据按主体、应用、scope、预算与有效期授权。

                                                  │

## AI 使用层模块

AI 使用层借鉴 Kirara AI 的分层思想，但定义自己的 TypeScript 契约和产品语义。

### 接入适配器

把 Web、IM、CLI 或未来 App 的输入转换为统一消息信封，把领域事件转换回平台输出。适配器只处理传输、平台身份映射和能力差异，不组装角色提示词，不决定计费。

### 会话路由

根据主体、应用、会话和模式定位会话，选择工作流，并执行并发与取消策略。它不直接调用供应商。

### 上下文服务

按策略组合角色、世界、用户资料、知识检索、长期记忆和最近消息。每个来源有 token 预算、优先级、作用域和引用信息。

### 工作流运行时

执行版本化工作流图或受控步骤序列。工作流只能调用能力注册表中的块；每个块声明输入、输出、权限、副作用、超时、重试和计费类别。

### 能力注册表

登记模型对话、嵌入、搜索、画图、ASR、TTS、记忆读写等能力。注册表提供稳定能力 ID，不把供应商模型名暴露给领域层。

### 领域存储

通过仓储接口保存会话、角色、世界、知识、记忆和偏好。当前文件存储是适配器实现，不是领域契约；迁移数据库时保持领域 ID 和 schema 版本。

## 统一 API 网关模块

API 网关以 New API 为上游基座，但燕中模块定义独立的业务边界。

### 协议入口

接收 OpenAI-compatible 请求和燕中控制面请求，执行大小限制、schema 校验、鉴权入口与错误映射。路由处理器不拥有计费和渠道规则。

### 主体与策略

把 Key 或 grant 解析为 `subject + application + scopes + policy`，执行模型/能力、来源 IP、预算、RPM、TPM、并发和有效期检查。

### 能力目录与路由

把稳定能力 ID 或公开模型名解析为内部模型族，再依据健康、成本、区域、权限和渠道状态选择设施适配器。客户端不得指定内部渠道 ID。

### 供应商适配器

负责请求/响应协议转换、流式事件归一、用量提取和错误分类。它不直接修改余额，不定义用户权限。

### 计量与计费

先生成请求级预留，再根据标准化实际用量结算差额；失败时退款。所有状态以同一 `request_id` 和幂等键写入不可变流水。异步任务在具备持久化状态机前保持关闭。

### 审计与观测

记录路由决策、策略拒绝、计费状态、供应商结果和延迟指标。敏感内容与凭据不进入普通日志；管理员信息与用户可见信息分层。

## 核心数据所有权

| 数据 | 权威写入者 | 其他系统允许保存 |
| --- | --- | --- |
| 用户主体、角色、停用状态 | 主站 | 不可变 `sub`、最小角色缓存、事件处理游标 |
| OAuth 客户端 | 主站 | 本服务自己的 client ID 与 Secret 引用 |
| 虚拟 Key、策略、grant | API | 掩码、短期加密会话凭据 |
| 公益额度与消费流水 | API | 只读余额和 request ID 展示 |
| 模型与能力目录 | API | 带版本和 TTL 的只读缓存 |
| 供应商凭据与内部渠道 | API/设施层 | 不允许下发到客户端或 AI 领域存储 |
| 会话、角色、世界 | AI 使用层 | 客户端短期 UI 状态、导出副本 |
| 知识、记忆与向量索引 | AI 使用层 | 可重建索引、引用和摘要 |
| 主站内容与活动 | 主站 | 只读展示缓存或来源链接 |

跨系统复制必须说明同步方向、失效策略和删除传播。没有这些信息的复制视为架构缺陷。

## 请求生命周期

```text
客户端生成 client_request_id
  → 接入适配器建立 trace_id
  → 身份或 Key 解析为主体
  → AI 使用层选择工作流并组装上下文
  → API 网关校验能力与策略
  → 创建 request_id 和额度预留
  → 路由选择设施/供应商适配器
  → 标准化流式事件和实际用量
  → 结算或退款
  → 观测事件关联 trace_id / request_id
  → 客户端收到稳定错误或完成事件
```

- 客户端重试复用 `client_request_id`；网关据此避免重复扣费。
- 工作流内每次付费能力调用拥有独立 `request_id`，共享同一 `trace_id`。
- SSE 断开不自动等于上游失败；结算以网关确认的上游结果和实际用量为准。

## 扩展点与准入

| 扩展点 | 最小契约 | 准入要求 |
| --- | --- | --- |
| 接入适配器 | 消息信封、平台能力、发送结果 | 身份映射、去重、速率限制、附件约束 |
| 工作流块 | schema、权限、输入输出、副作用 | 确定性验证、超时、取消、审计、版本 |
| 能力适配器 | 能力描述、执行请求、标准结果 | 白名单、成本归属、错误分类、资源限制 |
| 供应商适配器 | 标准模型请求/事件/用量 | 契约测试、流式取消、价格与故障验证 |
| 存储适配器 | 仓储接口与迁移能力 | 隔离、并发、备份、恢复、schema 版本 |
| 观测导出器 | 结构化事件和指标 | 脱敏、背压、失败不阻断主链 |

Preview 期不支持从公网动态下载并执行插件。插件市场启用前必须先完成签名、来源、权限、版本冲突、卸载和应急禁用机制。

完整扩展与插件规范见 `extensions.md`；计费状态机与观测标识分别见 `billing-and-ledger.md` 和 `observability.md`。

## 依赖方向

```text
UI / Transport
      ↓
Application / Workflow
      ↓
Domain contracts
      ↑
Adapters / Infrastructure
```

- 领域层不导入 Next.js、Gin、GORM、LiteLLM SDK 或供应商 SDK。
- 适配器实现领域端口；应用层通过依赖注入选择实现。
- 跨仓契约由 `docs/contracts.md` 定义，项目内部类型不得反向成为生态标准。

## 演进规则

1. 新功能先落在正确模块；不能确认归属时先写 ADR。
2. 触及集中式文件时，优先抽出一个有测试的真实边界，而不是继续增加分支。
3. 新供应商先通过适配器契约测试，再进入路由与计费验收。
4. 新能力先定义成本和失败语义；无法结算的能力不得使用公益额度。
5. 新客户端只接公开契约；发现需要读取内部字段时，先补契约而不是复制实现。
6. 旧接口退场必须有消费者清单、兼容窗口、观测指标和回滚路径。
