# AI 角色、世界与剧情状态

本文定义角色、世界、会话快照与剧情状态的关系。当前产品能力以 `燕中生态项目关系.txt` 为准，工作流和消息契约见 `ai-preview-blueprint.md` 与 `contracts.md`。

## 模型边界

```text
Persona Definition       World Definition
        \                    /
         \                  /
          v                v
          Conversation Snapshot
                    |
                    v
               Plot State
                    |
                    v
            Messages and Events
```

- Persona Definition 描述可复用角色，不绑定单一世界或会话。
- World Definition 描述环境、规则、时间线和故事资料，不绑定固定角色阵容。
- Conversation Snapshot 记录开场时采用的角色、世界和用户角色版本，保证历史可解释。
- Plot State 记录该会话发生过什么，只属于单个故事实例。
- Messages 是交互记录，不承担世界配置或状态机真值。

修改角色或世界定义只影响新快照。已开始的会话必须由用户明确选择升级版本，不能静默改变既有历史。

## 角色定义

角色至少包含：稳定 ID、owner、schema version、名称、简介、角色设定、说话风格、开场白、示例、标签、来源和更新时间。头像、封面、语音偏好和扩展字段均为可选引用。

约束：

- 预设、自建、复制和导入来源可区分；复制不抹除外部版权与来源。
- 角色删除不自动删除历史会话快照；相关知识、记忆和媒体按用户选择及保留规则处理。
- 私有角色默认只有 owner 可读。公开分享需要独立审核与撤回状态，不通过一个 `public` 布尔值直接开放。
- 角色设定是不可信内容，不能覆盖系统安全策略、工具权限、费用来源或 owner scope。

## 世界定义

世界至少包含：稳定 ID、owner、schema version、标题、说明、规则、时间线、故事大纲、标签、来源和更新时间。

长资料不直接全部放进提示。世界资料进入与知识相同的分块、检索和来源流程；时间线和核心规则保留有界摘要。世界删除不破坏已有快照，但新的会话不能继续引用已删除定义。

## 会话快照

会话创建时保存：

- workflow ID 与版本；
- 角色快照列表及来源 ID、来源版本；
- 可选世界快照及来源 ID、来源版本；
- 用户在该会话中的角色；
- 导演/主持配置；
- 内容与能力策略版本。

快照只包含运行所需角色和世界字段，不复制知识全文、长期记忆、凭据或账本。知识与记忆根据 owner 和角色 ID 在运行时读取，并记录使用的片段来源。

旧会话必须保持可读。新增字段使用版本迁移或可选默认；改变快照语义时提供显式升级和回滚，不在读取时不可逆改写原数据。

## 群聊工作流

一次群聊输入按以下步骤执行：

1. Adapter 创建统一用户消息和 workflow trace。
2. Router 选择固定版本的 group workflow。
3. Scheduler 读取允许的角色快照、世界摘要、剧情状态和最近消息，返回候选发言者与顺序。
4. Context Assembler 为每个发言角色独立组合角色、世界、用户角色、知识、记忆和消息预算。
5. Model Capability 为每个角色创建独立 request ID，并可并行执行允许的分支。
6. Event Stream 以确定顺序发布增量与完成事件。
7. 所有必要分支完成后，状态服务提交消息和 Plot State；部分失败保留可解释结果与重试边界。

Scheduler 只能从会话中已有角色选择，不创建隐式角色，不获得额外知识权限，也不直接写消息。导演配置用于场景或顺序；是否产生可见导演消息由 workflow schema 明确声明。

## 剧情状态机

当前世界快照与文本注入已经可用；奇遇、选择分支和剧情时间推进仍属于后续状态机，不应靠模型自由文本暗示“已经触发”。

正式 Plot State 至少包含：

- schema version 与单调 revision；
- 当前剧情时间或阶段；
- 已触发事件 ID；
- 有限、类型化的 flags；
- 最近一次产生状态的 workflow run ID；
- 并发更新条件和更新时间。

Encounter Definition 声明稳定 ID、触发条件、前置事件、可见内容、允许效果和版本。引擎先用确定性规则判断候选，再允许模型生成表现文本；模型不能直接写任意 flag 或跳过前置条件。

状态变更采用比较 revision 的原子提交。并发请求冲突时重新读取并返回稳定 conflict 错误，不以最后写入覆盖另一条剧情。

## 导入、导出与兼容

角色卡支持 chara_card_v3 兼容映射。导入流程需要：

- 校验文件类型、大小、schema 和危险内容；
- 保存原格式版本、来源、版权和未知扩展字段；
- 将外部字段映射到燕中领域对象，不在运行时直接依赖外部 JSON；
- 预览差异后由用户确认写入；
- 不自动导入远程资源、脚本、凭据或私有资料。

导出默认只包含用户有权发布的角色定义与兼容扩展，不包含知识、记忆、会话、世界、内部 owner ID、媒体 Secret 或网关字段。

世界格式在出现真实交换需求前保持燕中内部 versioned schema，不宣称行业兼容。

## 仓储与迁移

Persona、World、Conversation 和 Plot State 分别通过 Repository 端口持久化。当前文件适配器必须支持 owner 校验、schema 版本、原子写入、并发控制、损坏检测和备份。未来数据库适配器通过相同合同测试。

跨对象创建会话需要一个应用事务边界：读取定义、建立快照、创建会话和初始事件要么全部成功，要么留下可清理且不对用户可见的失败记录。不能靠多次无补偿的文件写入拼接。

## 内容与隐私

- 校园预设经过人工审核，不使用未经同意的真实人物身份、肖像、经历或私人关系。
- 面向未成年人的预设不采用性化、操控或不适当亲密关系设计。
- 用户自建内容仍受适用规则约束；举报、撤回和删除作用于公开分享，不替用户私有创作做无边界监控。
- 日志只记录 ID、版本、步骤、状态、耗时和费用，不记录完整角色、世界或消息正文。
- 分享角色或世界前显示将被公开的字段，并明确排除知识、记忆和会话。

## 验收

- 修改或删除定义不改变已有会话快照。
- owner 不能读取、复制或导出他人的私有角色与世界。
- 群聊每个角色只获得自己的知识与记忆，所有模型请求关联同一 trace。
- 调度、并行发言、取消和部分失败产生确定、可恢复的消息顺序。
- 旧 schema 数据可读、可迁移、可回滚；导入未知字段不会静默丢失。
- 剧情状态并发更新不会覆盖，事件只能触发一次，模型不能越权写状态。
- 删除、导出、分享和账号清理覆盖所有关联对象并有可验证结果。
