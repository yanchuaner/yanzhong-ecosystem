# 燕中生态愿景

## 定位

燕中生态是服务燕川中学校友、在校生、教师和共建者的开源数字基础设施。它以可信成员身份为起点，把内容、活动、AI 能力、学习、创作与开源协作连接成长期可维护的公共平台。

生态不是多个站点的并列集合。每个产品共享同一套身份边界、能力入口、账本规则、品牌语言和贡献方式，同时保留清晰的数据所有权与独立部署能力。

## 核心价值

### 可信连接

主站维护成员身份与状态，其他产品只消费最小身份声明。用户停用、角色变化和会话撤销能够沿契约传播，不通过复制用户表维持表面一致。

### 开放能力

模型、知识、工具和 Agent 能力通过统一 API 网关提供。网页、小程序、CLI 和未来客户端使用相同的权限、额度、错误和审计语义，避免每个产品重新接入供应商。

### 公益可持续

公益额度、活动权益和未来 BYOK 分账管理。每次由生态承担成本的调用都可归因、可解释、可结算、可退款、可审计。Preview 期不接在线支付；线下收款后由管理员按幂等凭证发放额度。

### 开源共建

正式生态代码统一采用 AGPL-3.0。架构、契约、部署和贡献路径公开，成员可以理解系统、复现实验、提交改进并接手维护。学习仓库用于练习，不把未经重新设计和评审的实验代码直接迁入生产。

### 自主生态 IP

燕中生态拥有自己的产品命名、视觉系统、协议、模块模型、默认内容和用户体验。第三方项目可以作为参考、依赖或上游基座，但不能成为燕中产品身份或跨项目契约的来源。

## 长期架构目标

- 身份、账本和业务数据各有唯一真值，不形成隐式共享数据库。
- 所有生态客户端围绕版本化契约协作，而不是依赖某个仓库的内部实现。
- AI 使用层由接入适配器、会话路由、工作流、能力块和上下文服务组成，可独立增加 Web、IM 或 Agent 入口。
- AI 设施层由统一网关屏蔽供应商协议、渠道和成本差异，可替换 LiteLLM 或单个上游而不修改业务客户端。
- 可观测性贯穿身份、工作流、模型调用和结算，使用同一 `request_id` 与 `trace_id` 关联，但不记录敏感正文。
- 每个公共模块都有所有者、版本、测试、迁移方式和失效策略。

## 成功标准

生态达到可持续状态时，应同时满足：

1. 新客户端只阅读公开契约即可接入身份和 AI 能力，无需访问其他项目数据库。
2. 新模型供应商只实现设施适配器和能力映射，无需修改 AI 产品领域逻辑。
3. 新工作流块声明输入、输出、权限、成本和副作用后即可组合，不绕过网关与审计。
4. 任一请求可以从用户操作追踪到工作流、模型路由、结算流水和错误原因。
5. 任一核心服务都具备备份、恢复、回滚、依赖清单和交接说明。
6. 对外界面体现统一燕中品牌，同时依法保留第三方归属与源码提供入口。
7. 新贡献者能在隔离环境中完成开发、测试和首次 PR，不依赖私人知识。

## 阶段口径

- **已实现**：代码和自动化测试存在，不代表真实环境可用。
- **已验收**：在隔离或真实链路中按文档完成验证，并保存可复核结果。
- **Preview**：可小范围运营、可回滚、可交接，仍允许收缩能力和调整契约。
- **正式版**：经过真实用户、成本、安全、恢复和长期运维验证，且兼容策略稳定。

当前阶段事实只在 `docs/燕中生态项目关系.txt` 维护。
