# 燕中生态基础设施边界

本文定义环境、部署、Secret、数据保护和可观测性原则。端口、镜像和当前运行状态以各项目部署文档与阶段真值为准。

事件字段、追踪、指标与告警的详细契约见 `observability.md`；威胁模型、数据分级和安全响应见 `security-and-privacy.md`。

## 环境分层

| 环境 | 用途 | 数据要求 | 外部访问 |
| --- | --- | --- | --- |
| 本地开发 | 单仓开发与单元测试 | 假数据、项目本地依赖 | 默认无公网依赖 |
| 隔离集成 | 跨仓契约、迁移、故障注入 | 可销毁数据库与独立 Secret | 仅受控测试上游 |
| Staging | HTTPS、界面与发布候选验收 | 与生产隔离，不复制隐私数据 | 受限成员 |
| Production | 正式 Preview 服务 | 真实数据、最小权限、完整备份 | 仅登记域名和端口 |

不得使用生产数据库验证迁移脚本。Staging 不作为第二身份源，不与生产共享签名密钥、OAuth 客户端或数据库。

## 生产拓扑

```text
Internet :443
    │
  Nginx
    ├─ yanchuaner.cn       → 主站服务
    ├─ api.yanchuaner.cn   → 统一 AI API 网关
    ├─ ai.yanchuaner.cn    → AI Web/BFF
    └─ lab.yanchuaner.cn   → Lab

Internal only
    ├─ PostgreSQL / SQLite / Redis
    ├─ LiteLLM 设施适配器
    ├─ Open WebUI 过渡客户端
    └─ 管理、备份与观测端点
```

公网只开放 80/443 和受控 SSH。数据库、Redis、LiteLLM、Open WebUI 与内部管理端口不加入公网安全组。

## 构建与发布

- 正式构建在 WSL/Linux 使用锁定依赖完成，生产服务器只导入产物。
- Preview 运行标签为 `preview`，同时保留“日期-短哈希”追溯标签。
- 镜像、Node、Go、Python 和数据库版本由项目锁文件或部署清单固定。
- 发布前保存当前配置、数据备份和回滚产物；发布后执行健康、身份、核心 API 和观测检查。
- 数据迁移与应用切换分开执行；迁移失败不得继续切流。

## Secret 与凭据域

| 凭据 | 所有者 | 可见范围 |
| --- | --- | --- |
| 主站签名/OIDC Secret | 主站 | 主站进程和对应客户端配置 |
| YanCore 交换 Secret | API 与单个可信 BFF | 不与 OIDC Secret 复用 |
| 供应商 API Key | API/设施层 | 渠道适配器，不下发使用层 |
| 用户虚拟 Key | API | 明文只显示一次，服务端保存哈希 |
| AI 会话应用 Key | API 签发、AI BFF 短期持有 | 加密 HttpOnly 会话，不暴露浏览器脚本 |
| 用户 BYOK 媒体凭据 | AI 凭据域 | 仅对应用户和能力适配器 |

- Secret 只通过权限受控的环境文件或凭据库注入。
- 日志、错误、追踪、备份清单和截图不包含明文。
- 轮换按凭据域独立执行，记录消费者、旧值失效时间和验收结果。
- 曾进入对话、Issue 或终端共享记录的真实密钥视为泄露并轮换。

## 数据与存储

- 数据卷、数据库和上传目录由各服务独立拥有，不挂载到其他业务服务读取。
- 缓存不是真值；Redis 故障时身份撤销、限流和计费按安全策略 fail-closed 或明确降级。
- 文件存储数据带 schema 版本和迁移工具；不能把目录结构当跨服务 API。
- 向量索引必须可由知识原文和嵌入配置重建。
- 删除请求同时覆盖权威数据、派生索引、缓存和可控备份保留策略。

## 备份与恢复

每个服务定义恢复单元：

- 主站：数据库、上传、配置与签名密钥引用；
- API：控制面数据库、日志/流水数据库、Redis 持久化、渠道和配置；
- AI：会话/角色/世界/知识/记忆数据、加密设置和必要媒体；
- Lab/CLI：源码、构建配置和发布产物，通常不含生产业务数据。

备份至少一份离机加密保存。恢复演练使用隔离环境，验证校验和、schema、行数/对象数、应用健康和关键业务链路。未演练的备份不视为可恢复。

## 可观测性

### 公共关联

- 入口生成或接收 `trace_id`。
- 每次网关付费调用生成 `request_id`。
- 客户端重试复用 `client_request_id` 或幂等键。
- 部署记录 `service`、`environment`、提交和镜像摘要。

### 最低指标

- HTTP/SSE 请求量、状态、P50/P95 延迟和断流；
- OIDC 登录、身份事件投递、积压和撤销延迟；
- 网关策略拒绝、RPM/TPM/并发和渠道健康；
- 预扣、结算、退款、待对账和余额一致性；
- 工作流与能力块耗时、失败、取消和降级；
- CPU、内存、磁盘、连接池、队列和备份结果。

### 脱敏

默认不记录消息正文、知识片段、上传内容、Authorization、Cookie、grant、Key、邮箱、手机号和第三方完整错误体。主体需要关联时使用内部 ID 或不可逆哈希，并限制管理员查询权限。

## 资源边界

- 服务器负责鉴权、策略、工作流、上下文、持久化与模型转发。
- 浏览器或设备负责录音、播放、解码、视图渲染和可控的并发拉流。
- 客户端承担计算不改变数据所有权；可靠会话和账本仍写入服务端真值。
- 异步媒体转码、批处理和任务队列在持久化状态、计费与取消机制完成前不得隐式启用。

## 故障原则

- 身份不确定：拒绝写操作和付费调用。
- 账本或限流后端不可用：不向付费上游派发新请求。
- 观测导出失败：主链可继续，但本地缓冲有上限并产生告警。
- 知识检索失败：可按工作流策略降级到无检索对话，但必须标记降级。
- 单渠道失败：仅在幂等、计费和能力兼容确认后自动切换。
