# 燕中 AI 产品与使用层蓝图

本文定义 `ai.yanchuaner.cn` 的产品范围、领域模块和扩展边界。当前已上线能力以 `燕中生态项目关系.txt` 为准，跨系统职责以 `architecture.md` 和 `contracts.md` 为准，项目内部实现见 `../ai_yanchuaner/docs/architecture.md`。

## 产品定位

燕中 AI 是认证成员的 AI 工作台，同时也是燕中生态的 AI 使用层。它把会话、角色、知识、记忆、世界、媒体和工具组织成可复用工作流，通过统一 API 网关获得模型能力。

它不承担：

- 公开注册、成员审核或第二套账号系统；
- 供应商渠道管理、额度真值、扣费、退款或 API 转售；
- 未经治理的公开角色市场、任意代理或第三方插件执行；
- 以共享服务账户冒充逐成员成本归因。

产品面向普通成员和生态开发者。普通成员使用清楚、可撤销的工作流；开发者复用同一消息、能力和网关契约，不为每个工具重新接模型。

## 产品界面

当前核心入口分为：

| 入口 | 主要任务 | 数据所有者 |
| --- | --- | --- |
| 工作台 | 最近会话、常用能力、额度摘要和入口导航 | AI 使用层；额度只读自 API |
| 聊天舞台 | 普通助手、角色扮演、群聊和媒体交互 | AI 使用层 |
| 角色库 | 私有角色的查看、创建、编辑、复制、导入导出和收藏 | AI 使用层 |
| 世界库 | 私有世界定义、快照和开场配置 | AI 使用层 |
| 资料与记忆 | 用户资料、角色资料、检索结果、长期记忆和删除 | AI 使用层 |
| 账户与用量 | 身份摘要、网关能力、额度与流水入口 | 主站与 API 的只读投影 |

页面必须覆盖加载、空、错误、权限不足、额度不足、生成中断和重试状态。移动端与桌面共享领域动作和契约，不复制业务流程。

## 使用模式

### 普通助手

处理问答、总结、写作整理和校园活动辅助。默认使用通用聊天能力，不注入角色设定。涉及外部搜索、文件或媒体时，界面明确展示所用能力和数据出口。

### 角色扮演

在普通消息之外组装一个角色快照、可选世界、相关知识和长期记忆。角色定义与对话历史分离；角色修改不静默改写已有会话快照。

### 多角色群聊

一次用户输入由调度步骤选择发言角色，再为每位角色独立组装上下文和调用模型。导演或主持能力只负责场景与顺序，不借此获得额外数据权限。每次模型调用具有独立 request ID，并共同关联到一次工作流 trace。

## 领域模块

```text
Web adapter
    |
message envelope -> session router -> workflow runtime
                                      |
                +---------------------+---------------------+
                |                     |                     |
          context assembly      capability registry    event stream
                |                     |                     |
       persona / world / RAG     model / media / tool      UI
       memory / preferences            |
                                      v
                            unified API gateway port

repositories: conversation / persona / world / knowledge / memory / settings
```

### 接入适配器

把 Web、未来 IM 或其他客户端输入转换为统一消息信封，把工作流事件转换回平台输出。适配器负责传输、平台身份映射和能力降级，不组装领域提示、不选择供应商、不计算费用。

### 会话路由

根据会话模式和已发布 workflow ID 选择工作流。路由只判断“运行哪个工作流”，不内嵌 RAG、群聊或模型实现。

### 工作流运行时

按版本化定义执行步骤、校验输入输出、传播取消和超时、记录事件并终结状态。首批内置工作流为 `chat`、`roleplay` 和 `group`；它们复用相同块协议，不复制完整处理器。

### 上下文组装

各贡献者返回有来源、作用域、优先级和预算的 Context Fragment。系统策略、用户偏好、角色快照、世界快照、知识检索、长期记忆和当前对话按确定顺序合并。任何贡献者都不能覆盖更高优先级安全策略。

### 能力注册表

能力以稳定 ID 声明输入、输出、所需 scope、副作用、费用来源、超时、数据出口和可用状态。工作流依赖 `text.chat.general`、`embedding.retrieval.multilingual`、`media.tts` 等能力，不硬编码供应商模型名。

### 仓储端口

领域服务通过 Conversation、Persona、World、Knowledge、Memory 和 Settings Repository 读写。当前文件实现是适配器，必须带 schema 版本、原子写入、所有者校验、备份和迁移；未来数据库实现不改变工作流和页面契约。

## 消息与事件

内部消息使用 `contracts.md` 定义的统一信封，至少包含消息 ID、会话 ID、发送主体、内容块、时间和 trace。内容块可表示文本、图片引用、音频引用和工具结果；二进制内容不直接嵌入事件日志。

工作流向适配器发布稳定事件：

- `run.started`、`step.started`；
- `message.delta`、`message.completed`；
- `capability.requested`、`capability.completed`；
- `run.failed`、`run.cancelled`、`run.completed`。

流式连接断开不等于模型和计费状态确定。服务端传播取消并依据网关请求状态查询最终结果。

## 角色与世界

- Persona 是可复用角色定义，包含公开设定、说话风格、示例、来源和 schema 版本。
- Conversation 保存使用时的角色与世界快照，保证历史会话可解释。
- World 是可复用环境、规则、时间线与故事资料，不强制绑定角色。
- Plot State 属于具体会话；奇遇、分支和时间推进需要版本化状态机，不能靠提示词隐式维护。
- 导入与导出保留来源、版权、扩展字段和格式版本。默认不携带私有资料、记忆、凭据或会话。

详细设计见 `ai-story-worlds.md`。

## 知识与记忆

- 知识是用户主动维护的资料，分为用户级和角色级，通过检索选择相关片段。
- 记忆是从对话中提取、可查看和删除的长期事实或摘要，与原始对话和知识资料分开。
- 检索、摘要与重排调用统一网关，纳入能力、额度和审计；不建立隐藏的免费模型链路。
- 每个上下文片段记录来源和作用域；角色、世界、用户和会话之间默认不串读。

详细设计见 `ai-knowledge-rag.md`。

## 媒体与用户凭据

媒体分为浏览器采集与播放、AI 媒体能力、服务端元数据三部分：

- 录音、播放、并发拉流和可由设备完成的转码优先留在浏览器。
- 图片理解、图片生成、ASR 和 TTS 通过能力端口调用，不散落供应商协议。
- 文件保存稳定引用、所有者、类型、大小、校验值、来源和保留期；消息只引用媒体 ID。
- 用户自配凭据与主站令牌、YanCore grant 和网关应用 Key 分库存储、分用途解密、可撤销，不进入日志或导出。

BYOK 能力开放前必须完成域名白名单、SSRF/DNS 重绑定防护、加密轮换、使用提示、删除、审计和供应商条款检查。

## 扩展机制

扩展顺序固定为：内置模块、静态注册表、版本化 SDK、受控第三方插件。只有前一层有真实使用和测试后才开放下一层。

工作流块和插件清单至少声明：

- 稳定 ID、版本、兼容 API 和入口；
- 输入输出 schema、scope 和副作用；
- 文件、网络、模型、知识、媒体和用户数据权限；
- 费用来源、超时、重试、资源上限和并发；
- 来源、许可证、签名、升级、禁用和卸载方式。

外部插件不进入主进程环境，不读取全局 Secret，不绕过统一网关，不直接写账本。插件市场在隔离、审核、撤销和故障恢复完成前不开放。

## 参考边界

Kirara AI 用于研究接入适配器、工作流、记忆、媒体、插件和可观测性如何分层。燕中使用层采用自己的 TypeScript 契约、领域模型、界面和品牌，不复制其源码、插件包、Logo 或产品叙事。

LiteLLM 属于可替换设施适配器，不是 AI 产品领域层。New API 是 API 控制面的上游基座，也不定义 AI 工作流。Open WebUI 仅作内网过渡与兼容回退，不是燕中自主产品入口。

来源与许可证规则见 `upstream-and-ip.md`。

## 隐私与内容治理

- 默认私有，不公开角色、知识、记忆、世界或会话。
- 用户可以查看、导出和删除自己拥有的数据；删除语义必须覆盖索引、派生摘要和媒体引用。
- 日志与审计默认不记录正文，只记录主体、能力、状态、耗时、费用和脱敏标识。
- 面向未成年人和校园场景的预设内容需要人工审核、举报和撤回路径。
- 学业辅助强调解释、结构和反馈，不提供绕过教学要求的自动提交能力。
- 公开分享、搜索或推荐需要独立的审核、版权、隐私和退出机制。

## 演进门槛

1. 统一消息、错误、工作流事件和 trace 进入机器可读 schema。
2. Web 页面拆分为领域状态与 action，网络访问集中到适配器。
3. `chat`、`roleplay`、`group` 通过同一工作流运行时。
4. 文件数据通过版本化仓储端口读写，并完成数据库迁移演练。
5. 第二个接入适配器复用同一工作流后，稳定适配器 SDK。
6. 内置能力权限与审计闭环后，再评审外部插件和公开分享。

每个增量同时完成契约、测试、观测、品牌、来源和回滚，不等待 Preview 全部结束后集中重构。
