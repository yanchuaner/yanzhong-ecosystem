## 真值层级

| 层级 | 内容 | 维护位置 |
| --- | --- | --- |
| 规范真值 | 愿景、架构、契约、扩展、安全、品牌、许可与治理 | 根 `docs/` |
| 状态真值 | 阶段、验收事实、下一阻断项 | `燕中生态项目关系.txt` |
| 实现真值 | 本仓模块、数据模型、运行方式 | 子仓库 `docs/` 与代码 |
| 历史证据 | 阶段记录、PoC、验收报告 | 子仓库阶段文档，标注日期和状态 |
| 决策历史 | 选择、理由、代价、回滚 | `decisions/` |

发生冲突时，代码说明“现在如何运行”，状态真值说明“已验收到何处”，根级规范说明“允许如何演进”。发现冲突必须同时修正文档，不能择一忽略。

## 文档完成标准

- 标题和开头能说明文档唯一回答的问题。
- 状态、目标和历史证据明确分开。
- 路径、命令、端点和仓库名称可验证。
- 规则有所有者、适用范围和失败处理。
- 跨仓字段链接到契约，不在多个项目重新定义。
- 第三方来源和燕中自主边界表述准确。
- 不包含密钥、个人信息、内部地址或生产数据。
- 不使用对话口吻、过程旁白、宣传腔或没有退出条件的愿望清单。

文档改动至少执行：

```bash
python3 docs/validate.py
```

治理仓使用 `make check` 执行独立门禁；完整工作区使用 `make check-workspace` 追加项目级检查。验证器检查治理入口、注册表、相对链接、品牌不变量与禁词、明显对话式模板语、许可证元数据、发布依赖审计脚本及全部生态 JSON Schema。
