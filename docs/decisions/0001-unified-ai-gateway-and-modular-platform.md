# 0001：统一 AI API 网关与模块化平台边界

- 状态：已采纳
- 日期：2026-08-13
- 影响：`api_yanchuaner`、`ai_yanchuaner`、`yczx_code`、后续 AI 客户端与插件

## 背景

AI Web 已具备对话、角色、世界、知识、记忆、群聊和媒体能力，API 已具备渠道、虚拟 Key、策略、额度和流水。继续按页面、供应商或单个客户端增加逻辑，会形成重复身份、重复路由、重复计费和无法替换的第三方依赖。

## 决策

1. `api.yanchuaner.cn` 是生态唯一公开 AI API 网关，也是模型策略和账本真值。
2. `ai.yanchuaner.cn` 是 AI 使用层，负责消息、会话、上下文、工作流和能力编排，不直接拥有供应商路由与用户余额。
3. LiteLLM 降为可替换设施适配器；New API 是 API 仓库的上游基座，均不定义燕中跨仓契约。
4. AI 使用层采用接入适配器、会话路由、上下文服务、工作流运行时和能力注册表边界。
5. 扩展先使用构建期注册和管理员白名单；外部动态插件在安全模型完成前保持关闭。
6. 现有实现按增量迁移，不暂停生产链路，也不等待 Preview 完成后一次性重写。

## 理由

- 身份、权限、成本和审计必须在所有客户端之间保持一致。
- 使用层需要独立于 Web 和供应商，才能复用到 IM、App 和 Agent。
- 设施组件迭代快，不能把其字段和路由规则固化为生态协议。
- 渐进迁移能持续交付，同时通过契约测试控制重构风险。

## 代价

- 需要维护燕中自己的 schema、能力目录和契约测试。
- 迁移期存在旧 OpenAI-compatible 字段与新能力语义并存。
- AI Web 和 API 都要拆分现有集中式实现，并承担兼容适配成本。
- 可插拔能力不能立即等同于开放插件市场。

## 回滚

若新模块边界导致生产回归，流量可回退到已验证的现有 Web BFF 与 `/v1` 路径；新契约保持只读或兼容适配，不删除旧数据。回滚不改变主站身份源和 API 账本真值，也不重新开放客户端直连供应商。
