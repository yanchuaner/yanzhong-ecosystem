# AI 知识与检索契约

本文定义燕中 AI 中知识、检索与长期记忆的职责和演进边界。当前上线范围以 `燕中生态项目关系.txt` 为准，AI 使用层架构见 `ai-preview-blueprint.md`。

## 领域边界

| 对象 | 来源 | 用途 | 生命周期 |
| --- | --- | --- | --- |
| 知识资料 | 用户主动粘贴或上传 | 检索相关事实 | 用户查看、替换、删除 |
| 知识片段 | 资料分块的派生数据 | 向量检索与来源定位 | 随资料重建或删除 |
| 向量 | 嵌入模型产生的派生数据 | 相似度搜索 | 模型或分块版本变化后重建 |
| 长期记忆 | 对话中提取的事实或摘要 | 跨会话保持连续性 | 用户查看、修正、清除 |
| 会话消息 | 用户与工作流的原始交互 | 当前会话上下文 | 服从会话保留与删除策略 |

知识不等于记忆，向量不等于原始资料。删除原始资料时必须删除或失效其片段、向量、缓存和索引；清除记忆不能删除用户上传的知识。

## 所有权与作用域

当前支持用户级与角色级知识。所有对象必须含稳定 owner ID 和 scope：

- `user`：仅该成员的允许工作流可检索；
- `persona`：仅该成员拥有的指定角色可检索；
- `conversation`：如后续增加，只在单个会话内有效；
- `world`：如后续增加，随世界授权和快照规则使用。

服务端从认证会话取得 owner ID，不接受客户端声明所有者。查询、删除、重建和导出都同时约束 owner 与对象 ID。角色卡导出、世界分享和公开角色默认不携带知识、记忆、向量或内部存储 ID。

## 写入流水线

```text
text or approved file
       |
validate type, size and ownership
       |
normalize -> split -> fingerprint
       |
embedding capability through unified gateway
       |
atomic repository write: document + chunks + vectors + status
```

每次导入记录资料 ID、原始名称、来源类型、内容校验值、分块版本、嵌入能力/模型版本、状态和时间。相同 owner、scope 与校验值的重复导入应复用或明确提示，不重复收费和生成孤立片段。

上传限制在允许的文本格式；PDF、Office、网页和图片解析在解析器具备大小、内容类型、恶意载荷与版权检查前不默认开启。原始文件是否保留必须有明确策略，不能由临时目录偶然决定。

## 检索流水线

1. 工作流根据会话与角色确定允许的知识作用域。
2. 对查询进行长度、语言和空内容校验。
3. 通过 `embedding.retrieval.multilingual` 能力取得查询向量。
4. Repository 在 owner 与 scope 范围内返回候选片段和来源。
5. 应用阈值、top-k、去重、字符/token 预算和可选重排。
6. 返回带来源、得分、scope 和片段 ID 的 Context Fragment。
7. Context Assembler 按优先级和预算合并，不让资料覆盖系统安全策略。

群聊按实际发言角色分别检索，再在该角色上下文中去重。一个角色的私有资料不能因同处群聊而进入另一角色上下文。

默认参数属于运行配置，不是公共契约。改变分块、阈值、top-k 或嵌入模型时记录版本，并用固定中文、英文、短问句、否定问题和无答案样本做回归。

## 网关与计费

嵌入、重排和记忆摘要均通过 `api.yanchuaner.cn` 的稳定能力 ID 调用：

- 使用层不连接供应商、不保存渠道密钥、不硬编码默认供应商；
- API 负责能力映射、模型白名单、限流、额度、账本和 request ID；
- 上传引发的多个嵌入批次共同关联一次工作流 trace，每个付费请求仍有独立 request ID；
- 部分批次失败时，资料进入明确的 `partial` 或 `failed` 状态，不把不完整索引标为可用；
- 重试只处理可证明幂等的批次，并避免重复扣费。

当前真实嵌入链路使用 SiliconFlow `BAAI/bge-m3`；这是状态事实，不是领域契约。替换渠道或模型不应修改知识服务。

## 仓储端口

核心服务依赖以下行为，而非 JSON 文件或特定数据库：

- 创建、列出、读取和删除资料；
- 原子替换资料派生的片段与向量；
- 按 owner、scope、embedding version 查询候选；
- 标记处理中、可用、部分失败、失败和待重建；
- 导出原始资料与可解释元数据；
- 按 owner 完整删除并证明无残留。

当前 `/data` JSON 与进程内检索作为 File Repository Adapter 保留。它需要 schema 版本、原子替换、并发锁、损坏检测、备份与迁移测试。数据库或向量索引适配器应与文件适配器通过同一 repository contract suite；规模增长不是建立边界的前提。

## 长期记忆

记忆生成是独立工作流步骤，不直接藏在消息保存逻辑中：

1. 按配置的消息窗口触发候选提取。
2. 通过统一网关生成结构化候选事实或摘要。
3. 校验长度、owner、角色、来源消息范围和敏感字段。
4. 去重并写入 Memory Repository。
5. 在后续上下文中按用户、角色和会话规则读取。

用户必须能查看和清除记忆。正式开放自动事实记忆前还应支持修正或拒绝候选；高敏感信息默认不沉淀。删除来源会话后，派生记忆按公开保留规则清除或标记失去来源。

## 当前接口

当前 AI BFF 提供：

- `GET/POST /api/personas/[id]/knowledge`
- `DELETE /api/personas/[id]/knowledge`
- `DELETE /api/personas/[id]/knowledge/documents/[docId]`
- `GET /api/personas/[id]/knowledge/chunks`
- `GET/POST /api/me/knowledge`
- `DELETE /api/me/knowledge/documents/[docId]`

这些 HTTP 路径属于 Web 适配器。领域服务和未来 IM 适配器不得通过内部 HTTP 回调复用业务，而应调用相同应用服务。接口响应逐步迁移到通用错误、request ID 与 trace 契约。

## 隐私与安全

- 默认私有，静态数据和备份按敏感用户内容保护。
- 日志不记录正文、向量、完整文件名或用户查询；观测只记录大小区间、片段数、耗时、状态和脱敏 ID。
- 资料内容属于不可信输入，不能通过提示注入改变系统策略、工具权限或数据作用域。
- 展示检索来源时只显示当前 owner 有权查看的资料名称与片段。
- 导出使用可读原始资料和元数据，不以供应商向量作为可移植格式。
- 账号删除覆盖知识、片段、向量、记忆、缓存、媒体关联和可恢复备份的后续清理策略。

## 验收

- owner、角色和群聊成员之间无越权检索；直接猜测 ID 也被拒绝。
- 相同资料重复导入不生成重复费用或孤立向量。
- 嵌入部分失败、超时和取消产生可恢复状态。
- 删除资料后，检索、缓存、导出和重建队列均不可再访问。
- 固定检索样本在分块、模型或存储迁移前后有可解释结果。
- File 与未来数据库适配器通过同一合同测试，并可在隔离数据上往返迁移。
- 任一次检索可通过 trace 关联嵌入、重排、上下文注入和账单，但日志不泄露正文。
