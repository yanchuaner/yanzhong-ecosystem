# 燕中生态演进路线

本文只定义顺序与退出条件。当前完成度见 `燕中生态项目关系.txt`，具体缺陷见 `architecture-review.md`。

## 路线原则

- 先稳定契约，再增加消费者。
- 先完成计费终态，再扩大付费能力。
- 每个产品增量同时改善模块边界，不把重构集中留到 Preview 末尾。
- 品牌、文档、许可证和可观测性属于功能完成标准，不是发布后的收尾。
- 平台能力至少有两个真实实现或消费者后才宣称稳定，不预建空插件框架。

## R0：治理与契约基线

目标：所有仓库围绕同一身份、网关、账本、模块和品牌规则协作。

交付：

- 生态架构、跨系统契约、架构审查和 ADR 形成真值。
- 各仓库 AGENTS 与项目架构文档声明数据所有权、依赖方向和扩展点。
- 自主代码许可证统一为 AGPL-3.0，第三方归属与源码入口保持完整。
- 统一术语：使用层、统一 API 网关、设施适配器、工作流块、request ID、trace ID。
- 建立按锁文件和发布产物执行的依赖审计、SBOM 与限时风险接受流程。
- 根级治理文件、schema 与 ADR 已纳入独立治理仓；继续要求 `main` 分支保护，并让 API、AI 与 Web 以不可变提交或版本固定所消费的契约。

退出条件：文档链接和许可证检查通过；各仓库不存在互相冲突的身份、账本和 LiteLLM 职责表述；公开产物没有未经评估的 high/critical 依赖公告；生态规范拥有独立提交历史和 PR 审计。

## R1：稳定调用与结算

目标：把现有真实模型链路变成可复核的平台能力。

交付：

- 标准错误码和请求/追踪标识贯穿 AI Web、API 与设施层。
- 同步模型请求状态机完整覆盖预扣、结算、退款和待对账。
- 真实上游失败、断流、超时、预算耗尽、RPM/TPM/并发与 Redis 故障验收。
- 预算、渠道健康、未终结预留和身份事件积压告警。

退出条件：任一模型调用可按 request ID 对账；故障不会产生负余额、重复扣费或无终态预留。

## R2：AI 使用层模块化

目标：在继续产品迭代前，把 Web 入口迁移为第一个标准接入适配器。

交付：

- 统一消息信封和流式事件。
- 页面状态按领域拆分，网络调用集中到类型化客户端。
- `chat`、`roleplay`、`group` 成为版本化内置工作流。
- 知识、记忆、模型调用和媒体成为显式能力块或应用服务。
- 文件存储通过仓储端口接入并带 schema 版本。

退出条件：新增一个工作流或能力无需修改主页面控制器；Web 路由不包含角色/RAG/群聊领域分支。

## R3：网关控制面独立

目标：让燕中业务规则不再依赖 New API 内部表和界面结构。

交付：

- 燕中 Credential、Policy、Entitlement、Ledger 和 Request 形成清晰领域服务。
- 上游 Token 与渠道结构降为兼容投影和 relay adapter。
- 发布稳定能力目录，区分能力 ID、公开模型别名和内部渠道。
- 供应商适配器通过统一流式、错误、用量和取消契约测试。
- 明确 LiteLLM 保留能力和可替换路径，消除无意义双层路由。

退出条件：更换默认供应商或设施路由不修改 AI 使用层；上游升级不改变燕中账本语义。

## R4：生态客户端扩展

目标：证明统一契约可被不同形态的产品复用。

交付：

- YCZX Code 使用能力目录、统一错误和 request ID。
- 小程序只通过主站公开 API 使用身份、内容和活动能力。
- 选取一个真实的第二 AI 接入适配器，复用相同会话与工作流核心。
- Lab 发布可执行的接入教程、schema 和示例应用。

退出条件：至少两个客户端和两个接入适配器通过同一套契约测试，不复制身份或计费逻辑。

## R5：受控插件与工作流生态

目标：允许贡献者扩展能力，同时保持权限、成本与运维可控。

交付：

- 工作流 manifest、块 schema、scope、副作用、超时、重试和版本规则。
- 插件来源、签名、依赖、资源、网络和数据权限模型。
- 管理员启用、灰度、审计、紧急禁用、卸载和回滚。
- 插件开发包、示例、兼容矩阵和贡献审核流程。

退出条件：外部插件在隔离环境中无法越权读取凭据、绕过网关或修改账本；禁用后不影响核心聊天链路。

## R6：正式版运行能力

目标：将 Preview 的可演示链路提升为可持续运营系统。

交付：

- 数据保留、删除、导出和隐私授权规则。
- 全量备份恢复演练、跨版本数据迁移和灾难回滚。
- SLO、告警分级、值守、成本核对和安全响应。
- 统一燕中品牌资产、来源声明、源码提供入口和贡献者治理。
- Forum、Birthday 与 App 按治理和隐私门禁独立立项。

退出条件：核心链路经过真实用户、移动端、成本、安全、故障、恢复和交接验收。
