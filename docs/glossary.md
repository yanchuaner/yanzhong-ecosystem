# 燕中生态术语表

本文统一跨仓文档、API、界面和观测中的核心术语。术语描述职责，不绑定某个框架或第三方产品。

| 术语 | 定义 | 不等同于 |
| --- | --- | --- |
| 燕中 | 生态 IP 和核心关键词，是中文品牌与产品命名基础 | 另一个生态名称、仅限校内使用的简称 |
| `yanchuaner` | 生态 IP、核心关键词和稳定数字标识，用于域名、账号、仓库和技术命名空间 | 学校名称的英文翻译、另一套生态名称 |
| 燕中生态 | 生态唯一正式中文名称，指围绕统一身份、内容、AI 能力、账本与开源协作形成的项目网络 | 单一网站、第三方项目换皮、其他生态名称 |
| `Yanzhong Ecosystem` | “燕中生态”的统一英文名称 | 其他英文生态名称 |
| 燕川中学 | 学校法定名称及相关事实语境 | 燕中生态的另一个品牌名 |
| 主站 | `yanchuaner.cn` 身份、成员、内容、活动与运营系统 | 所有子项目的数据库或代码仓 |
| 主体 | 由主站稳定 `sub` 表示的成员身份 | 邮箱、用户名、本地用户 ID |
| 应用 | 使用主体授权和生态能力的登记消费者 | 任意 OAuth 回调或共享 Key |
| 使用层 | 将消息、会话、上下文、角色、知识、记忆和工作流组织为产品行为的层 | 模型供应商路由、用户账本 |
| 统一 AI API 网关 | `api.yanchuaner.cn` 对外发布的模型/能力入口、策略与计费边界 | LiteLLM 管理 API、New API 内部 Router |
| 控制面 | 管理主体凭据、策略、能力、渠道、价格、权益和审计的 API 领域 | 用户聊天页面、供应商数据面 |
| 设施层 | 数据库、缓存、对象存储、协议代理与供应商连接等可替换运行实现 | 跨仓业务契约 |
| 能力 | 可被发现、授权和调用的稳定操作，例如聊天、嵌入、检索或 TTS | 供应商模型名、某个 HTTP 路径 |
| 能力 ID | 与供应商无关的稳定标识，例如 `text.chat.general` | 渠道 ID、部署名、模型 SKU |
| 模型别名 | 网关公开、可映射到内部实现的兼容名称 | 稳定能力本身、供应商渠道 |
| 模块 | 拥有明确领域职责、数据和端口的代码边界 | 任意目录或页面组件 |
| 端口 | 由领域或应用层声明、供适配器实现的接口 | 网络端口、供应商 SDK 类型 |
| 适配器 | 将外部平台、协议、存储或供应商映射到稳定端口的实现 | 拥有业务策略的服务 |
| 接入适配器 | 将 Web、微信、IM、CLI 等输入/输出映射为统一消息和事件 | 角色提示、余额和供应商路由 |
| 供应商适配器 | 将标准模型请求、流式事件、用量和错误映射到某个上游 | 主体授权和账本写入 |
| 设施适配器 | 对 LiteLLM、存储、遥测等基础设施的可替换封装 | 产品使用层或业务真值 |
| 工作流 | 版本化组合能力块与状态转换的声明式编排 | 任意脚本或页面分支 |
| 工作流块 | 带输入/输出、scope、副作用、计费、超时、重试和幂等声明的步骤 | 可读取全局环境的函数 |
| 扩展 | 对已声明扩展点的一项内置或外部实现 | 自动获得运行权限的代码包 |
| 插件 | 核心仓之外发布、按不可信代码隔离并经 manifest 授权的扩展分发物 | 任意 npm/Python 包、远程 MCP 配置 |
| YanCore | 燕中主体、应用授权、短期 grant/Key 和身份事件相关协议与模块 | 所有燕中代码的通用前缀 |
| 权益 | 主体可使用的资金来源、额度、范围和有效期 | 供应商余额或 `users.quota` 投影 |
| 账本 | API 只追加记录权益和消费变化的审计真值 | 仪表盘余额、LiteLLM 成本表 |
| 预留 | 付费请求派发前持久化锁定的最大可用金额 | 内存计数、客户端估算 |
| 结算 | 按可信实际用量和价格版本确定最终费用并释放差额 | 本地 token 估算 |
| 待对账 | 上游费用结果不确定、必须保留有界预留并人工/自动核对的终态 | 成功、失败或自动退款 |
| `client_request_id` | 客户端对同一用户意图提供的幂等标识 | 网关账单主键 |
| `request_id` | 网关为一次付费业务请求生成的账本关联标识 | SSE 连接 ID、供应商请求 ID |
| `trace_id` | 一次用户操作或工作流跨服务传播的关联标识 | 用户 ID 或计费终态 |
| Schema 基线 | `docs/schemas/` 中已发布但可能尚未接入运行时的机器契约 | 已实现、已合同通过或已生产验收 |
| Preview | 能由受限成员使用、限制和回滚已说明的阶段 | Stable、完整安全或长期 SLA |

文档中需要使用第三方名时，明确其角色：New API 是代码上游，Kirara AI 是使用层架构参考，LiteLLM 是设施依赖，Open WebUI 是过渡客户端。不得用“AI 底座”“中台”“数据面”等未定义词替代具体职责；确需新增术语时先在本表定义。
