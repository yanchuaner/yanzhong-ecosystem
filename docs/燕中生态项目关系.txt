# 燕中生态阶段状态

更新日期：2026-08-13

本文件是生态阶段状态的唯一真值，只记录当前事实、验收范围、未闭环风险和带日期的里程碑。长期规则见 `architecture.md` 与 `contracts.md`，缺陷和迁移顺序见 `architecture-review.md` 与 `roadmap.md`。架构中存在某个模块或契约，不表示代码已经实现。

## 当前快照

总体状态：`PREVIEW_IN_OPERATION_AND_ARCHITECTURE_CONVERGENCE`

- `yanchuaner.cn`、`api.yanchuaner.cn`、`ai.yanchuaner.cn` 已形成真实身份、模型调用和逐主体账本链路。
- 主站是唯一身份源；燕中 API 的不可变流水是权益与消费账本真值。
- 自主 AI Web 已是公开 AI 产品入口。Open WebUI 只保留为内网过渡客户端，LiteLLM 只保留为可替换设施适配器与成本核对工具。
- 九份跨系统契约与一份仓库注册表已有生态级 JSON Schema 基线；提供方/消费者接入、契约测试、完整计费终态、端到端 trace 和 AI 使用层模块化尚未完成。
- 工作区根目录尚未纳入独立 Git 仓库，生态规范、schema 与 ADR 缺少可评审和可回滚的发布载体。
- 2026-08-13 的锁文件审计中，主站生产依赖未发现已知漏洞；API、AI、Lab 与小程序仍有未经完整可达性评估的 high/critical 公告，不能仅凭构建通过进入新发布。
- 小程序、Lab 和两个 YCZX 仓库处于不同成熟度，不能按主站、API、AI 的生产状态推定其已达到同等门槛。
- Forum、Birthday 与 App 尚未建立正式运行仓库，不属于当前已交付能力。

当前最高优先级：

1. 将根级治理文件、schema 和 ADR 纳入独立、受保护的版本控制与 PR 流程。
2. 评估并修复公开发布产物的 high/critical 依赖公告；临时接受项必须有证据、owner、缓解和到期日。
3. 完成真实上游失败、断流、超时、重试、退款和 request ID 对账。
4. 将统一错误、能力目录、消息信封、工作流事件和追踪 schema 接入提供方、消费者与契约测试。
5. 拆分 AI Web 大型页面控制器与对话处理器，建立工作流、能力和仓储端口。
6. 将燕中 Credential、Policy、Request 和 Ledger 语义进一步从 New API 内部结构中独立。
7. 按增量替换第三方可见品牌和临时资产，同时保留法定上游署名。

## 架构基线

2026-08-13 起，新增能力遵循以下依赖方向：

```text
Web / Mini Program / YCZX Code / future adapters
                    |
                    v
             AI usage layer
                    |
                    v
       api.yanchuaner.cn unified AI gateway
                    |
                    v
   provider and infrastructure adapters
```

- `web_yanchuaner` 拥有身份与主站内容。
- `ai_yanchuaner` 拥有会话、角色、世界、知识、记忆、媒体元数据和工作流。
- `api_yanchuaner` 拥有主体凭据、权限策略、能力与路由、额度、账本和模型审计。
- 客户端只依赖燕中发布的契约，不依赖供应商、渠道 ID、New API 表结构或 LiteLLM 管理对象。
- 模块通过版本化端口和 schema 扩展；未建立权限、版本、审计和隔离前不执行第三方插件。

这套基线约束所有新代码。现有代码按 `roadmap.md` 渐进迁移，不以 Preview 结束为重构起点。

## 当前生产链路

身份链路：

```text
member -> yanchuaner.cn OIDC -> downstream subject mapping
       -> signed identity event -> revoke grants, keys and sessions
```

自主 AI 调用链路：

```text
member
  -> ai.yanchuaner.cn OIDC session
  -> API verifies fixed UserInfo endpoint
  -> short-lived YanCore grant and application key
  -> AI BFF calls api.yanchuaner.cn/v1
  -> gateway policy, routing, reserve, settle/refund and audit
  -> approved provider adapter
```

Open WebUI 过渡链路使用受限服务账户，不继承个人主体，不扣减个人公益额度。LiteLLM 内部费用只用于设施成本核对，不能覆盖燕中账本。

## 状态口径

- `已实现`：代码和局部自动测试存在。
- `合同通过`：提供方与消费者对同一 schema 或 fixture 通过自动检查。
- `隔离验收`：使用可销毁数据和真实进程完成端到端流程。
- `真实上游验收`：使用获授权供应商和可撤销测试凭据验证调用、费用与故障。
- `生产验收`：在正式域名、正式身份和受控生产配置下完成，并有监控与回滚证据。

较低层级的结果不能替代较高层级。历史 PoC 使用本机兼容上游的结果，只证明协议和本地链路；DeepSeek 与 SiliconFlow 的已登记调用属于真实上游验收，但不证明所有供应商和故障路径均已通过。

## Preview 退出条件

- 核心身份、模型、计费和撤销路径没有未处理的 P0 问题。
- 任一付费请求可按 request ID 得到唯一终态并与不可变流水核对。
- API/AI 的机器可读契约与消费者合同测试通过，跨服务 trace 可定位群聊等扇出调用。
- 数据备份、恢复、迁移和故障回滚至少完成一次可重复演练。
- 小程序在真实设备与弱网下完成身份、隐私和活动闭环。
- 公开入口具备明确品牌、源码入口、许可证、第三方归属、安全披露和数据删除说明。
- 未达到上述门槛的能力继续标记 Preview、受控或规划，不以版本名称代替验收。
