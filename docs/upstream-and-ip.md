# 上游、许可证与燕中生态 IP

## 总原则

燕中生态对外呈现自主产品身份，对代码和资产来源保持完整、准确、可追溯的披露。品牌自主化不等于删除第三方归属；使用开源许可证也不自动取得上游商标、Logo 或作者身份。

燕中自主代码与原创文档统一采用 GNU Affero General Public License v3.0。包清单使用 SPDX 表达式 `AGPL-3.0-only`，仓库保留完整 AGPLv3 文本；第三方代码、字体、图片、模型、数据和文档继续适用各自许可证与条款。

## 燕中自主层

以下内容作为燕中生态长期维护的自主边界：

- 燕中品牌、域名、产品信息架构、设计令牌和默认内容；
- 主站身份与成员业务；
- YanCore 主体授权、应用 grant 和身份事件语义；
- 公益权益、哈希虚拟 Key、不可变流水与对账规则；
- 生态跨系统契约、能力目录和观测语义；
- 自主 AI Web、角色、世界、知识、记忆、群聊和工作流契约；
- YCZX Code、Lab、小程序和生态贡献流程。

自主边界必须有代码、测试、文档和来源登记支持，不能只通过改名、换色、格式化或 AI 改写宣称成立。

## 品牌架构

### 对外产品

- 使用“燕中生态”“燕中 AI”“燕中 API”“燕中实验室”“YCZX Code”等自主名称。
- 使用燕中 Logo、图标、色彩、语气、默认角色和帮助入口。
- 页面 metadata、favicon、登录页、错误页、邮件、分享图和安装包逐步纳入同一品牌清单。
- 提供“开源与法律声明”入口，链接源码、许可证、NOTICE 和第三方清单。

### 第三方组件

- 内部管理界面可保留上游原始品牌，避免误导其为燕中自主实现。
- 衍生界面允许增加燕中产品外壳，但不得移除许可证要求的法律通知、上游归属或商标限制。
- 上游 Logo 不作为燕中主品牌；移除或替换前先核对许可证、附加条款和商标规则。

## 品牌迁移顺序

1. 建立品牌资产清单：名称、Logo、favicon、颜色、字体、默认内容、域名、帮助与法律入口。
2. 优先替换自主公开入口：主站、AI Web、Lab、小程序和 YCZX Code。
3. 对 `api_yanchuaner` 区分燕中自主外壳与 New API 衍生界面；逐页记录保留的法律声明。
4. 将 Open WebUI、LiteLLM 等第三方管理界面保持内网，减少对外品牌依赖。
5. 每次发布扫描上游名称、Logo、默认链接和 metadata；合法必须保留的归属不计为品牌缺陷。

## 许可证执行

- 每个正式仓库保留 `LICENSE`、`NOTICE` 或第三方清单、`SECURITY.md` 和源码入口。
- 自主包元数据使用 `AGPL-3.0-only`；锁文件中的第三方许可证不被改写。
- 从 MIT、Apache-2.0 等依赖复制代码时保留原版权与许可文本；组合发布遵守兼容要求。
- AGPL 网络服务向远程用户提供对应源码获取方式。
- 教学或实验成果进入正式仓库前，确认贡献者有权按 AGPL-3.0 提供，并重新登记来源。
- 许可证或品牌条款不明确时，先隔离功能并记录问题，不以产品排期代替法律核对。

## 上游升级与替换

每次上游升级记录：

1. 上游版本、提交或镜像摘要；
2. 许可证和附加条款变化；
3. 本地修改与冲突范围；
4. 契约、数据迁移和兼容测试；
5. 回滚版本；
6. 来源矩阵、NOTICE 和第三方清单更新。

替换上游时先保持燕中契约不变，通过适配器并行验证，再迁移流量。不得让供应商或上游内部对象成为替换过程中的新公共接口。
